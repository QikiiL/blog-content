开篇前先讲一个梗图里的笑话：一位外国人盛赞中国开发者具有非常强的安全意识，因为他们从来不见中国开发者使用自己的真实IP访问GitHub。

## 笑点解析

并非是我们自己主动地去隐藏自己的真实IP访问GitHub，而是如果你想在国内能够流畅地访问GitHub的话，你就需要使用VPN/修改DNS（修改DNS不会改变自己的IP地址）等方法进行访问。

## 为什么国内的原生网络会出现这样的情况

### 1.Great Firewall of China（网络空间安全管理体系），简称GFW

> ~~这就是民间俗称的网络防火墙（所谓翻墙翻的就是这个墙）~~

它是部署在国内通往海外的网络出口，对进出的跨境网络流量做处理，主要技术手段有：

1\. DNS 污染：对部分境外域名，在解析过程返回虚假 IP，导致你解析不到真实服务器地址。

2\. IP 阻断：直接屏蔽某些 IP，就算解析正确，数据包也无法建立连接。

3\. 深度报文检测 DPI：分析 HTTPS 握手 SNI、数据包内容特征，识别之后发送 RST 复位包直接断开 TCP 连接。

4\. **流量限流**：不对网站完全封死，但对部分跨境链路做流量限制，表现为：可以连通，但速度极慢、丢包高，GitHub 就经常是这种状态。

### 2.CDN 节点问题（本篇重点）

GitHub 大量静态资源（图片、Release 安装包、页面组件）依赖海外 CDN，国内没有就近加速节点，这些资源加载失败，就会表现成 “页面打不开”。

### 3.网络链路跨洋传输距离远

GitHub 的服务器主要部署在海外，国内用户访问时，数据需要经过海底光缆、多条国际骨干网路由。跨洋链路本身距离长，物理上就会带来较高延迟；高峰期国际出口带宽拥堵，丢包变多，就会出现加载极慢、图片打不开、连接超时。
