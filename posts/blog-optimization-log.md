开篇前先讲一个梗图里的笑话：一位外国人盛赞中国开发者具有非常强的安全意识，因为他们从来不见中国开发者使用自己的真实IP访问GitHub。

# 笑点解析

并非是我们自己主动地去隐藏自己的真实IP访问GitHub，而是如果你想在国内能够流畅地访问GitHub的话，你就需要使用VPN/修改DNS（修改DNS不会改变自己的IP地址）等方法进行访问。

## 为什么国内的原生网络会出现这样的情况

### 1.Great Firewall of China（网络空间安全管理体系），简称GFW

> ~~这就是民间俗称的网络防火墙（所谓翻墙翻的就是这个墙）~~

它部署在国内通往海外的网络出口，对进出的跨境网络流量做处理，主要技术手段有：

1\. DNS 污染：对部分境外域名，在解析过程返回虚假 IP，导致你解析不到真实服务器地址。

2\. IP 阻断：直接屏蔽某些 IP，就算解析正确，数据包也无法建立连接。

3\. 深度报文检测 DPI：分析 HTTPS 握手 SNI、数据包内容特征，识别之后发送 RST 复位包直接断开 TCP 连接。

4\. **流量限流**：不对网站完全封死，但对部分跨境链路做流量限制，表现为：可以连通，但速度极慢、丢包高，GitHub 就经常是这种状态。

### 2.CDN 节点问题（本篇重点）

GitHub 大量静态资源（图片、Release 安装包、页面组件）依赖海外 CDN，国内没有就近加速节点，这些资源加载失败，就会表现成 “页面打不开”或者“打开缓慢”。

### 3.网络链路跨洋传输距离远

GitHub 的服务器主要部署在海外，国内用户访问时，数据需要经过海底光缆、多条国际骨干网路由。跨洋链路本身距离长，物理上就会带来较高延迟；高峰期国际出口带宽拥堵，丢包变多，就会出现加载极慢、图片打不开、连接超时。

# 说回GitHub Pages

GitHub Pages同样依托海外 Fastly CDN 分发资源，但使用独立的github.io域名与 CDN 节点池，只托管纯静态网页，不存在账号登录、代码提交这类动态交互流量。

因为域名和流量特征和github.com完全区分开，国内原生网络对github.io的干扰强度更低，所以很多时候可以直接打开。但这不代表它永远稳定，部分网络环境下 GitHub Pages 依旧会出现无法访问、加载缓慢的问题。

## 如何解决这个问题

这是本篇的重点章节，在开篇之前我先介绍一下CDN的背景知识。

### 1.什么是CDN

CDN 的全称是 **Content Delivery Network**，意为内容分发网络。

简单理解就是：把网站的静态文件（网页、图片、JS、安装包）提前复制到遍布全球各地的边缘服务器（CDN 节点）。用户访问时，不再直接去遥远的源站服务器拿文件，而是从离自己最近的节点获取资源，以此降低延迟、提升访问速度。

在使用CDN前，你需要先了解供应商的服务器部署在哪里，以及他的加速节点的覆盖范围。节点分布决定了不同地区用户能否命中就近缓存，直接影响访问延迟与可用性。如果你需要面向全球的访客，就需要选择拥有大量海外边缘节点的服务商，例如Cloudflare、 Fastly。但是如果你面向的主要访客是国内的用户，那么就需要找国内的厂商。国内厂商里同样具备海外边缘节点的主流服务商主要有：阿里云 CDN、腾讯云 CDN、华为云 CDN、网宿科技，还有七牛云、又拍云这类偏向开发者的 CDN 产品。

而开发者圈子里最常用、和 GitHub 生态强相关的，是jsDelivr，它和上面传统商业 CDN 定位不一样，jsDelivr 是面向开源项目的免费全球 CDN，底层依靠 Fastly 的全球边缘节点。它的核心功能是直接分发托管在 GitHub、npm、WordPress 上的静态资源，包括 JS、CSS、图片、字体等前端文件。开发者不需要自己搭建服务器，只要把静态文件上传到 GitHub 仓库或者发布 npm 包，就可以直接通过 jsDelivr 的域名引用资源。

但它有一个很现实的短板：cdn.jsdelivr.net 域名在国内原生网络访问不稳定，经常出现资源加载转圈、超时失败的情况。很多 GitHub Pages 站点页面骨架能打开，但页面样式、脚本、图标全部丢失，大多就是因为页面引入了 jsDelivr 的资源，国内无法正常拉取。

为了解决这个问题，国内开发者社区衍生出了 JSDMirror（cdn.jsdmirror.com)，它是 jsDelivr 的国内镜像 CDN，底层依托腾讯云 EdgeOne，在中国大陆部署边缘节点。

它的工作逻辑：用户请求资源时，访问的是国内 CDN 节点；节点如果已经缓存该文件，直接返回；缓存不存在，则由节点出境回源，从 jsDelivr / GitHub 获取原始静态资源并缓存到国内节点。后续其他国内用户访问同一份文件，直接读取国内缓存，不再重复跨境请求。

### 2.如何使用CDN

GitHub Pages 本身不会自动引入 jsDelivr。是你选用的静态站点模板（Jekyll/Hugo/Astro 等），模板默认写死了 jsDelivr 的资源地址。

所以修改位置就在模板的网页源码：

1\. Jekyll（GitHub Pages 原生默认引擎）

* 全局搜索仓库里的 html、md、\_includes/、\_layouts/、\_config.yml
* 一般在页面头部 \_includes/head.html，这里写了 CSS、JS、图标库的 cdn 引入代码

2\. Hugo/ Astro等其他静态框架

*  在主题配置文件或者 layout 模板内，找到资源引用代码

举个 Jekyll 典型示例（\_includes/head.html）

```htmlbars
<!-- 模板自带原版，国内访问容易挂 -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/xxx/theme@v1.0/assets/style.css">

<!-- 替换域名之后 -->
<link rel="stylesheet" href="https://cdn.jsdmirror.com/gh/xxx/theme@v1.0/assets/style.css">
```
